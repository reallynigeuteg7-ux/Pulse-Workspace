# Pulse

Приложение на C# / WPF для коротких контролируемых HTTP-тестов своего сервера. Чёрно-белый интерфейс, локально включённый Montserrat с кириллицей. В сборке есть нагрузочный GET-тест и проверка доступности; функций DDoS, эксплуатации уязвимостей и перебора паролей нет.

## Запуск

1. Распакуйте **весь архив** в одну папку.
2. Откройте `Pulse.exe`. Папка `assets` и файл `Pulse.exe.config` должны оставаться рядом.
3. Укажите адрес сервера, включая `http://` или `https://`, и нажмите **Проверить**.
4. Задайте частоту и длительность, затем нажмите **Запустить тест**.
5. **Стоп** или **Esc** отменяет текущие запросы. **Ctrl+Enter** запускает тест.
6. После завершения нажмите **Экспорт CSV**, чтобы сохранить полный отчёт.

Нужны Windows и .NET Framework 4.8 или 4.8.1. Для готового EXE не нужны .NET SDK, NuGet, установка шрифта или права администратора. Запуск приложения сам по себе не отправляет запросы. Указанный по умолчанию `localhost:8080` — пример: сервер на нём приложение автоматически не запускает.

## Возможности

- Один HTTP(S)-адрес, GET-запросы и просмотр заголовков ответа.
- Заданная частота **1–100 запросов/с** и длительность **5–120 секунд**; по умолчанию — 100 запросов/с.
- Максимум **4 одновременных запроса**. Если все заняты, слот пропускается; отложенной очереди и догоняющих серий нет.
- Тайм-аут запроса **5 секунд**, включая чтение тела. Приложение читает максимум **64 КиБ** тела ответа.
- Автостоп при **HTTP 429/503** или **пяти последовательных ошибках соединения**.
- Среднее время до заголовков ответа (TTFB), P95, доля ошибок, график и последние шесть запросов на экране.
- История последних **20 тестов текущей сессии** и экспорт каждого из них.
- Полный CSV с параметрами, причиной остановки, пропущенными слотами и результатом каждого начатого запроса.

Метод всегда GET. Редиректы, cookies, автоматические учётные данные, системный прокси и прикладные повторные попытки отключены. TLS-сертификаты проверяются стандартными средствами Windows. Самоподписанный сертификат должен быть доверенным на компьютере; обхода проверки в программе нет.

## Как читать результаты

**Отклик** измеряется от отправки запроса до получения заголовков. Это не время полной загрузки страницы, выполнения JavaScript или рендеринга браузером. График показывает среднее TTFB по секундам начала запросов.

**P95** рассчитывается методом ближайшего ранга по полученным ответам. Сетевые ошибки без заголовков не входят в среднюю задержку и P95.

**Успешный запрос** — ответ 2xx без ошибки чтения тела. Ответы вне 2xx и сетевые сбои входят в долю ошибок. Отменённые запросы показаны отдельно и не включаются в число завершённых или долю ошибок. На момент автостопа часть запросов может уже выполняться; они отменяются и остаются в отчёте.

Частота — верхняя граница планировщика. Медленный сервер, лимит соединений и планировщик Windows могут снизить фактическую частоту. Ограничение тела относится к чтению приложением; сетевой стек может заранее буферизовать дополнительные байты. В .NET Framework системное разрешение DNS иногда длится дольше тайм-аута запроса; на локальном сервере отдельно проверены отмена и пятисекундный тайм-аут.

## CSV и хранение

CSV записывается в UTF-8 с BOM, разделитель — запятая, дробная часть чисел — через точку. Первая секция содержит параметры теста, после пустой строки идёт таблица запросов. При импорте в Excel выберите UTF-8 и разделитель «запятая». Временные метки в CSV — UTC; история на экране использует местное время Windows.

Автоматического сохранения адресов и ответов на диск нет. История очищается при закрытии приложения. CSV сохраняется только по выбранному пользователем пути; заголовки ответа в CSV не включаются.

## Исходники и сборка

Откройте `Pulse.csproj` в Visual Studio с компонентами разработки классических .NET-приложений и targeting pack .NET Framework 4.8. Проект без сторонних NuGet-зависимостей.

Или выполните в папке приложения:

```powershell
.\build.ps1
```

Скрипт использует встроенный компилятор .NET Framework. Он создаёт `Pulse.exe` и копирует конфигурацию рядом. XAML включается в EXE как ресурс; TTF-файлы поставляются отдельно в `assets/fonts`.

Основные файлы:

- `src/LoadEngine.cs` — ограничения, запросы, статистика и CSV.
- `src/Dashboard.xaml` — интерфейс и стили.
- `src/Dashboard.cs` — управление интерфейсом и отрисовка графика.
- `src/Program.cs` — запуск приложения и генерация PNG-превью.

## Проверки

```powershell
.\build.ps1 -Test
.\test-ui.ps1
```

Тесты создают временный TCP-сервер только на `127.0.0.1` и случайном свободном порту. Внешние серверы не используются. Нужна разрешённая локальная сетевая связь. После теста слушатель и соединения закрываются.

14 проверок движка охватывают валидацию, GET, редиректы, ограничение тела, частоту, длительность, параллелизм, пропуски, 429/503, отмену, тайм-аут заголовков и тела, остановку при сетевых ошибках, статистику и CSV. Семь проверок интерфейса охватывают загрузку Montserrat с кириллицей, минимальный размер окна, валидацию, проверку адреса, обновление метрик и графика, навигацию/остановку, закрытие во время теста.

`test-ui.ps1` создаёт PNG-снимки WPF в `tests/screenshots`. Он проверяет элементы самого приложения без управления другими окнами. Просмотр и закрытие диалога сохранения CSV автоматическими проверками не покрыты; сам экспорт проверен тестом движка.
